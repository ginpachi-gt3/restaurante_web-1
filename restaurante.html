Inicio / Producto

Vista general del producto

Qué es OrderFast, a quién está dirigido y por qué puede ayudar a tu restaurante a operar mejor.

¿A quién está dirigido?

OrderFast está pensado para restaurantes pequeños y medianos que quieren dejar atrás las libretas de papel y las hojas de cálculo.

  • Restaurantes familiares con 5 a 30 mesas
  • Cafeterías y comedores con menú fijo
  • Food trucks que necesitan control de inventario
  • Negocios de comida que recién empiezan

¿Qué problema resuelve?

La mayoría de restaurantes pequeños pierden dinero por errores de inventario, mesas mal asignadas o falta de visibilidad sobre sus ventas reales.

  • Elimina las libretas de pedidos escritos a mano
  • Evita vender platillos sin existencia
  • Muestra en tiempo real qué mesas están ocupadas
  • Permite saber cuánto se ha vendido sin hacer cuentas

¿En qué se diferencia?

A diferencia de otros sistemas, OrderFast no requiere servidor web, ni conexión a internet, ni suscripciones mensuales.

  • Sin cuotas mensuales: se instala una vez y funciona
  • Funciona en red local, sin depender de la nube
  • Un solo archivo Python fácil de mantener
  • Interfaz en español para usuarios no técnicos

Beneficios en números

⏱️

Menos tiempo

Registrar un pedido toma menos de 30 segundos.

📉

Menos errores

El inventario se actualiza solo.

📈

Más control

Reportes al instante de ventas.

💰

Cero costos

Sin licencias ni suscripciones.

💡 Sobre el nombre "OrderFast" "Order" viene de la idea de tomar pedidos y "Fast" hace referencia a la velocidad con la que el sistema permite registrar y cobrar una orden.

Características del sistema

Consultas SQL que utiliza

-- Listar todos los empleados
SELECT id_empleado, nombres, apellidos, telefono,
       cargo, salario, estado
FROM empleado
ORDER BY id_empleado DESC;

-- Insertar un empleado nuevo
INSERT INTO empleado

Inicio / Módulos / Pedidos

Módulo de Pedidos

El corazón del sistema. Registra las ventas con múltiples platillos.

¿Cómo funciona?

La pantalla tiene tres zonas: arriba el selector, abajo a la izquierda el carrito y a la derecha el resumen.

  • Elige la mesa (solo las Disponibles)
  • Selecciona un platillo del menú
  • Define cantidad y presiona "Agregar"
  • Repite hasta completar el pedido
  • Guarda y el sistema hace el resto

Lo que ocurre al guardar un pedido

1

Se crea el pedido

Se inserta una fila en pedido.

2

Se guarda el detalle

Cada producto va a detalle_pedido.

3

Se actualiza todo

Stock descontado y mesa ocupada.

Transacción completa en SQL

-- 1) Insertar el pedido principal
INSERT INTO pedido (id_mesa, id_usuario, cliente, estado, total)
VALUES (%s, %s, %s, 'Pendiente', %s);

-- 2) Por cada producto del carrito
INSERT INTO detalle_pedido
(id_pedido, id_platillo, cantidad, precio, subtotal)
VALUES (%s, %s, %s, %s, %s);

-- 3) Descontar inventario
UPDATE platillo
SET existencia = existencia - %s
WHERE id_platillo = %s;

-- 4) Ocupar la mesa
UPDATE mesa SET estado='Ocupada' WHERE id_mesa=%s;
✓ Todo o nada Las cuatro operaciones se ejecutan dentro de la misma transacción. Si cualquiera falla, se revierte con rollback.
Inicio / Módulos / Reportes

Módulo de Reportes

Consulta el desempeño del negocio con datos reales.

¿Qué permite hacer?

Módulo de solo lectura que muestra tres indicadores clave calculados con funciones de agregación de SQL.

  • Ver cuántos pedidos se han cobrado
  • Ver la suma de ventas acumuladas
  • Conocer el ticket promedio
  • Listar todos los pedidos con estado y fecha
  • Marcar pedidos pendientes como pagados

Indicadores que calcula

✓

Pedidos pagados

Cuenta los pedidos con estado Pagado.

$

Ventas

Suma del campo total.

↗

Promedio

Ticket medio con AVG().

Consulta SQL de los indicadores

SELECT
    COUNT(*)              AS cantidad,
    COALESCE(SUM(total),0)  AS ventas,
    COALESCE(AVG(total),0)  AS promedio
FROM pedido
WHERE estado = 'Pagado';
💡 Dato importante Solo los pedidos con estado Pagado cuentan como ventas. Los pedidos quedan en Pendiente al crearse.

Cómo se cifra la contraseña

import hashlib

def hash_password(texto):
    """Convierte una contraseña en SHA-256."""
    return hashlib.sha256(texto.encode("utf-8")).hexdigest()
⚠️ Protección contra auto-bloqueo El sistema impide que un Administrador desactive o elimine su propia cuenta mientras está conectado.

  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE TABLE usuarios (

  nombre          VARCHAR(120) NOT NULL,

);

Inicio / Documentación / Instalación

Guía de instalación

Sigue estos pasos en orden para tener OrderFast funcionando.

1

Instalar Python 3

Descarga Python 3.8 o superior desde python.org. En Windows, marca la casilla "Add Python to PATH". 

python --version
# Debe mostrar algo como: Python 3.11.4
2

Instalar MySQL Server

Descarga MySQL Community Server e instálalo. Anota la contraseña del usuario root.

Importante OrderFast se conecta por defecto al puerto 3306 en localhost.
3

Crear la base de datos

Abre MySQL Workbench o la consola y ejecuta el script usuarios.sql. 

source ruta/completa/usuarios.sql
4

Instalar el conector de MySQL

Abre la terminal y ejecuta el comando de instalación. Es la única dependencia externa del proyecto. 

pip install mysql-connector-python
5

Configurar la conexión

Abre el archivo principal y edita las constantes de configuración al inicio. 

CONFIG_HOST     = "localhost"
CONFIG_USER     = "root"
CONFIG_PASSWORD = "TU_CONTRASEÑA_AQUI"
CONFIG_DATABASE = "restaurante_db"
6

Ejecutar el sistema

Guarda el archivo y ejecútalo con Python. Ingresa con la cuenta administrador por defecto. 

python orderfast.py
Credenciales iniciales Usuario: admin
Contraseña: admin123

Inicio / FAQ

Preguntas frecuentes

Las dudas más comunes sobre OrderFast, resueltas.

¿Necesito conexión a internet para usar OrderFast? +
No. OrderFast funciona completamente en red local. Solo necesita comunicarse con el servidor MySQL, que normalmente está en la misma computadora o en otro equipo de la red del restaurante.
¿Las contraseñas se guardan de forma segura? +
Sí. Las contraseñas nunca se almacenan en texto plano. Se convierten con el algoritmo SHA-256 antes de insertarlas en la base de datos.
¿Puedo cambiar los colores del sistema? +
Sí. Todos los colores están definidos como constantes al inicio del archivo Python. Cambiando esos valores hexadecimales cambia el tema completo de la aplicación.
¿Qué pasa si un empleado intenta entrar al módulo de usuarios? +
El botón de Usuarios solo se crea en la barra lateral si el rol del usuario conectado es Administrador. Si un empleado intentara acceder, el sistema muestra un mensaje de error.
¿Se puede usar el sistema en varias computadoras a la vez? +
Sí, siempre que todas las computadoras apunten al mismo servidor MySQL. Solo hay que cambiar la constante CONFIG_HOST.
¿Qué ocurre si se cae la conexión mientras guardo un pedido? +
El sistema usa transacciones. Si cualquiera de las operaciones falla, se ejecuta un rollback() que deshace todos los cambios.
¿Cómo agrego una categoría nueva al menú? +
Actualmente las categorías están definidas como lista en el módulo de platillos. Para agregar una nueva, busca la tupla de valores del ttk.Combobox de categorías en el código y añade el nombre.
¿El sistema genera facturas o comprobantes? +
No en esta versión. El sistema registra los pedidos y sus totales, y permite marcarlos como pagados, pero no imprime documentos fiscales.
¿Puedo personalizar el nombre del restaurante? +
Sí. El nombre de la aplicación aparece como constante APP_TITLE al inicio del archivo. Cambiando esa línea, el sistema mostrará el nombre de tu restaurante.
